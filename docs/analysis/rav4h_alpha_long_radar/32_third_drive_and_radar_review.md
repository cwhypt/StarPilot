## 3. 为什么 T3/T4 现在不会提高安全性

- **T3 低速 4 次（route 8 的 175 s、319 s、320 s）**：视觉 + 雷达都锁定前车，规划器已在约 -1.0 m/s² 减速；雷达要求 -0.76～-0.95，同一量级，接入无增益。
- **T3 高速 4 次（733.6 s、1121.7–1122.5 s，16–20 m/s，目标 45–55 m，要求 -2.85～-3.8）**：当时**无任何前车**（视觉、雷达 leadOne 都不存在）。视频：两处都是进匝道弯，正前方约 50 m 是弯道警示牌 / 护栏。雷达把路边静止物体当成碰撞目标。接入控制即为高速幻影重刹。1121.7 s 与 Chill 加速进弯是同一个弯。
- **T4**：6 段全是视觉也看到同一前车、规划器已在处理；B 的静止过滤没被路牌骗到（设计方向正确），但目前没有它要补的情况。

## 4. 雷达现在用在哪

1. **跟车测距（唯一影响控车）**：ARS510 只发一个 ACC 目标；radard 与视觉前车匹配后，`dRel`/`vRel` 用雷达值。影响跟车距离与减速、停在前车后的位置、Conditional 的前车与慢车判断。
2. **低速（< 4 m/s）雷达单独确认前车**：7.0 原有逻辑。
3. **FCW（只报警）**：规划器 FCW 接受雷达确认的前车（`e7b01d1`）；T2 雷达 PCS_ALARM。
4. **只记录**：REQUIRED_DECEL、B cap、`radarNoData` / `radarNoTarget` 健康提示。
5. 雷达掉线：退回纯视觉，不退出控制。

`aLeadK`（前车加速度）目前**不来自雷达**：由 radard 的卡尔曼滤波对 `vLead` 求导得到。

## 5. T5 `aRel` 评估

信号：`ACC_TARGET_1`（0x235，bus 1）`REL_ACCEL`，byte 2，`raw*0.125-12.5` m/s²，正值 = 拉开。离线比较 `REL_ACCEL + aEgo` 与当前 `leadOne.aLeadK`（仅雷达匹配的前车、车速 > 1 m/s）：

| | route 8（5953 样本） | route 6（584 样本） |
|---|---|---|
| 相关系数 | 0.93 | 0.82 |
| 偏差（雷达 − 卡尔曼） | -0.11 m/s² | -0.03 m/s² |
| 卡尔曼相对雷达滞后 | **0.45 s** | **0.55 s** |
| 逐帧噪声（差分标准差） | 0.12 vs 0.08 | 0.20 vs 0.14 |
| 无效值（-12.5） | 0 | 0 |

前车刹车片段（雷达 aLead < -1.5）：
- route 8 672.6 s（24 m/s，44 m）：雷达 -2.50，卡尔曼最低 -1.82，晚 1.65 s 才过 -1.5；684.6 s：雷达 -2.19，卡尔曼只到 -1.40。
- route 8 595.5 s：卡尔曼晚 1.3 s；低速片段卡尔曼晚 0.25–0.35 s。

结论：信号语义已确认（偏差小、方向一致），雷达值**更早约 0.5 s、高速时峰值更准**，噪声略高（0.125 分辨率）。收益：前车急刹时 MPC 更早减速。

实现跨度（估算）：
1. `ars510_acc_target.py`：解析 `REL_ACCEL` → `pt.deprecated.aRel`（约 5 行）。
2. `radard.py`：`Track.update` 接收 `aRel`；仅 ARS510 + 本选项时 `aLeadK = aRel + aEgo`（轻滤波，如 0.1–0.2 s 一阶），`vLeadK` 仍用卡尔曼；`aLeadTau` 逻辑不变（约 20–30 行）。注意 `aEgo` 与雷达周期的对齐。
3. 测试：非 ARS510 车型逐位不变；`aRel` 缺失/NaN 回退卡尔曼；数值换算（约 80–100 行）。
4. 影响面：`aLeadK` 进 MPC 前车外推、规划器 `pulse_lead`、慢车判断。属于行为改动，需要开关（参数键新增要重编 `params_pyx.so`，可考虑复用 `ToyotaRadarMode=2`）和实车验证跟车舒适度。
